## 3-A. 용어 판정 — `aiStatus` 화면 표기 (D16 승격 제안)

QA F7이 계약서 §3(`:403`)의 `미실행 / 분석 중 / 완료 / 실패`와 구현 `frontend/src/lib/terms.js:26–31`의 `공란 / 검토 중 / 검토 완료 / 자동 검토 실패`가 다르다고 보고했습니다. 기획서 5.6에 `aiStatus` 값이 없어 **아직 고정되지 않은 용어**이며, 용어 관리자로서 아래로 판정합니다.

구현이 계약서를 어긴 것이 아닙니다. `docs/screen-spec.md` 초판 §1.2에 제가 "검토 중 / 검토 완료 / 자동 검토 실패"로 적었고 `frontend-dev`가 그것을 따랐습니다. **표기를 잘못 정한 것은 저입니다.**

### 결정

| 내부 값 | 화면 표기 (SCR-02) | 비고 |
|---|---|---|
| SKIPPED | **(공란)** | 기획서 5.4의 "SKIPPED는 공란" 지시를 따름. 계약서의 "미실행"은 채택하지 않음 |
| PENDING | **분석 중** | 계약서 표기 채택 |
| COMPLETED | **분석 완료** | 계약서는 "완료". 컬럼 헤더에서 떨어진 자리에서도 주어가 살도록 어간을 붙임 |
| FAILED | **분석 실패** | 상세 패널 문장도 "자동 분석 실패 — 담당자 판단이 필요합니다" |

### 근거

**첫째, "검토"는 사람의 행위로 이미 예약된 단어입니다.** 5.6이 `PENDING_REVIEW`를 "검토 대기", `REVIEW` 액션을 "검토"로 고정했고 UC-06 전체가 사람의 확정 절차입니다. 감사 목록 한 행에는 판정 "검토 대기"와 AI 상태가 나란히 서는데, 후자까지 "검토 중"이면 **한 행에 "검토"가 두 번 나오면서 누가 무엇을 하는지 화면에서 구분되지 않습니다.** 기획서 4장 책임 경계가 이 프로젝트의 핵심 주장인데, AI의 상태를 사람의 동사로 부르면 그 주장이 화면에서 흐려집니다. AI는 분석하고 사람은 검토합니다.

**둘째, SKIPPED는 공란이어야 합니다.** 기획서 5.4가 명시했고, SSOT 계층상 기획서가 계약서보다 우선합니다. 게다가 데모 3:34에서 Case A 행의 빈 칸이 "규칙이 결정한 건에는 AI를 부르지 않았다"(0:44 대사)를 목록에서 다시 증명합니다. "미실행"이라는 글자가 있으면 무언가 실행 단계를 건너뛴 것처럼 읽히지만, 공란은 애초에 해당 없음으로 읽힙니다.

**셋째, 이 규칙은 SCR-02에만 적용합니다.** 직원용 SCR-01의 "보안 검토 중"(스피너)과 "자동 검토 실패 — 담당자 확인 중"은 기획서 5.3이 고정한 **프로세스 안내 문장**이므로 그대로 둡니다. 직원에게 필요한 것은 자기 프롬프트가 보안 검토를 받고 있다는 사실뿐이고 AI 개입 여부는 직원의 관심사가 아닙니다. **값 라벨은 행위 주체를 구분하고, 안내 문장은 기획서 문구를 따른다** — 이것이 두 화면의 표기가 갈리는 기준입니다.

### 기획서 5.6 추가 제안 (리더 수정용)

5.6은 판정·검토 상태만 담고 있어 `aiStatus`가 어디에도 고정되지 않습니다. 같은 일이 반복되지 않도록 아래 4행 추가를 제안합니다.

| 내부 값 | 화면 표기 |
|---|---|
| SKIPPED | (표시하지 않음) — AI 미호출 |
| PENDING | 분석 중 |
| COMPLETED | 분석 완료 |
| FAILED | 분석 실패 |

표 아래 각주 한 줄: "`aiStatus`는 AI의 상태이므로 '분석', `message.status`·`review_status`는 사람의 절차이므로 '검토'로 적는다. 직원 화면(5.3)의 프로세스 안내 문구는 예외."
