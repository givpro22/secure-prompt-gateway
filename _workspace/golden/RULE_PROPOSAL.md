# 규칙 후보 자동 생성 — 프로토타입

"AI가 놓친 사례를 모아 정규식을 쌓아가는 서비스"가 성립하는지 확인한 것이다.
**성립한다. 단 LLM에게 정규식을 쓰게 하면 안 된다.**

```bash
python3 propose_rule_slots.py     # 채택안
python3 propose_rule.py           # 기각안 (LLM이 정규식 직접 작성)
```

## 두 방식을 다 돌렸다

| 방식 | 결과 |
|---|---|
| LLM이 정규식을 직접 작성 | **5/5 기각.** 기존 규칙을 베끼거나 예시를 못 잡음 |
| LLM이 키워드·값 형태를 고름 | 3시행 중 1회 통과. `DIGITS6`를 고집함 |
| **LLM은 키워드만, 값 형태는 코드가 탐색** | **3/3 통과, 첫 시도에** |

같은 원리를 두 번 적용한 결과다 — 검사기에서 "span은 코드가 만들고 LLM은 라벨만
고른다"로 풀었던 것을, 여기서는 "정규식은 코드가 조립하고 LLM은 키워드만 뽑는다"로 풀었다.
**모델이 잘하는 일(문장에서 한국어 키워드 뽑기)과 못하는 일(정규식 작성·형태 선택)을
가른다.** 키워드는 모든 시행에서 `['주민번호','주민등록번호']`로 정확했다.

## 구조

```
① 규칙이 놓친 사례          ← 사람이 신고하거나 섀도 모드가 수집
② LLM이 문맥 키워드를 뽑는다  ← 여기만 LLM
③ 코드가 좁은 형태부터 조립   ← DATE6 → DIGITS_GROUPED → ALNUM8 → DIGITS6
④ RuleGate.java 가 판정      ← 실제 런타임과 같은 java.util.regex
⑤ 통과한 것만 사람 승인 화면  ← 활성화는 사람
```

### ④가 이 구조의 전부다

게이트를 통과하려면 셋을 동시에 만족해야 한다.

1. `java.util.regex`로 컴파일된다
2. 주어진 예시를 **전부** 잡는다
3. 참음성 267건 중 **하나도** 안 잡는다

Python `re`로 검증하면 안 된다 — Java가 지원하는 가변 길이 룩비하인드를 멋대로 기각한다.
`PII-ACCOUNT-06`이 이미 그 문법을 쓰고 있다.

**"AI가 정규식을 모아간다"가 위험하지 않은 말이 되는 건 이 게이트 때문이다.**
생성은 자동이고, 살아남을지는 골든셋이 정한다.

### 좁은 것부터 넣는 이유

`DIGITS6`(숫자 6자리)는 `주민번호 규칙이 123456 형태로 바뀌었어`를 잡는다.
`DATE6`(YYMMDD)는 34월이라 안 잡는다. 통과하는 **가장 좁은** 형태를 쓴다.

## 실제 산출물

입력 예시 3건에서 나온 것이다. 손으로 쓴 것과 거의 같다.

```
AI  (?<=주민번호[^\n]{0,8}|주민등록번호[^\n]{0,8})(?<![0-9])\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])(?![0-9])
사람 (주민(등록)?번호|생년월일)[^\n]{0,6}?(?<![0-9])(\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01]))(?![0-9])
```

## 한계

- **`mask_label`·`code`가 쓸 만하지 않다.** `****`, `JMB` 같은 값이 나온다. 사람이
  승인 화면에서 고칠 필드다. 패턴이 맞는지가 게이트의 관심사이고 이름은 아니다.
- **`생년월일` 키워드가 빠졌다.** 입력 예시에 그 단어가 없었다. 사례를 넓게 모아야 한다.
- **값 형태가 4종뿐이다.** 새 형태가 필요하면 사람이 템플릿에 추가하고 검증해야 한다.
  자동으로 늘어나지 않는다 — 그게 안전장치다.
- **①이 없다.** 사례 수집은 섀도 모드가 필요하고 이번 범위 밖이다. 지금은 예시를
  스크립트에 손으로 넣는다.

## 왜 이게 필요한가 — `주민번호 001123`

`PII-RRN-01`은 13자리를 전부 요구한다. `주민번호 001123이야?`는 앞 6자리뿐이라
`ALLOW`로 통과한다. 그리고 **AI도 이 문장을 보지 못한다** — AI는 규칙이 REVIEW를
낸 건에만 불리기 때문이다.

설령 봤어도 못 막는다. AI가 만들 수 있는 것은 `SUGGESTED` 후보뿐이고 `MASK`를
만들 수 있는 것은 규칙뿐이다. **가려야 하는 것은 반드시 규칙이 잡아야 한다.**
그래서 규칙을 늘리는 경로가 필요하다.
