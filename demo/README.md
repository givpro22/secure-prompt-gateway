# 시연 파일 — 끌어다 놓는 순서

번호대로 창에 끌어다 놓으면 됩니다. **복사·붙여넣기 하지 않습니다** — 시연 중 오타 하나로
판정이 달라지고, 그 자리가 가장 설명하기 어렵습니다.

파일을 놓으면 표에서 뽑은 텍스트가 **입력창에 그대로 보입니다.** 파일은 브라우저 밖으로
나가지 않고, 나가는 것은 화면에 보이는 그 문자열입니다. 첫 파일에서 이 점을 먼저 말합니다.

**발표자용 대본은 `발표대본.md`에 있습니다.**

생성과 판정 대조는 `make_demo_files.py`가 합니다.

```
python3 make_demo_files.py            # 파일 생성
python3 make_demo_files.py --verify   # 배포 서버에 넣어 기대 판정과 대조
```

## 각 파일에서 짚을 것

### 1 — 통과가 기본이다
걸릴 것이 하나도 없습니다. 통제 서비스를 소개하면서 첫 장면이 차단이면 "쓰기 불편한
물건"으로 읽힙니다. **평소에는 아무 일도 일어나지 않는다**를 먼저 보입니다.

### 2a → 2b — 차단은 막다른 길이 아니다
차단 화면에 규칙 ID·의무·출처가 함께 뜹니다. 입력창의 원문은 지워지지 않습니다.
접속 문자열을 환경변수 이름으로 바꾸고 주민번호를 빼면 같은 일을 계속할 수 있습니다.

### 3 — 부서가 판정을 바꾼다
**같은 파일**을 계정만 바꿔 두 번 붙입니다. 영업팀에는 고객사 정책(P-CONF)이 적용되고
개발팀에는 없습니다. 정책은 코드가 아니라 `department_policy` 매핑에서 옵니다.

### 4 — 시간이 판정을 바꾼다 / 정한 쪽과 걸리는 쪽
해제일 2026-09-20이라 아직 막힙니다. 같은 파일을 홍보팀 계정으로 붙이면 통과합니다 —
엠바고를 **정한 부서**와 **적용받는 부서**가 다르기 때문입니다 (D19 `owner_dept_id`).

### 5 — 해제일이 지나면
2026-09-04, 발표 당일에 풀립니다. 05와 같은 모양의 문장이 통과합니다.
날짜가 코드가 아니라 `policy_rule.embargo_until`에 있어서 가능한 장면입니다.

### 6 — 마스킹이 어떻게 동작하나, 그리고 오탐
**이 순서에서 마스킹이 처음 나오는 자리입니다.** 예비 파일을 빼면서 "정상 마스킹" 장면이
없어졌으므로 여기서 마스킹의 동작을 먼저 말한 뒤 오탐으로 넘어갑니다.

> 규칙이 전화번호 **형식**을 잡아 라벨로 치환했습니다. 여기까지가 마스킹입니다.
> 그런데 이건 전화번호가 아니라 **부품 코드**입니다.

부품 코드가 전화번호 형식이라 가려집니다. 규칙은 문맥을 모릅니다.
여기서 **검토 요청**을 눌러 사유를 적고, 보안팀 계정으로 옮겨 원문과 마스킹본을 나란히
놓고 확정합니다. 확정하면 요청자 화면에 알림과 결과가 돌아옵니다.

### 7 — 나간 뒤까지
내부 IP·연락처가 가려져 나갑니다. 그리고 **답변이 저절로 돌아옵니다.**
모델이 고친 코드를 통째로 되돌려주면 사내 코드가 외부를 한 바퀴 돈 셈이라
`LEAK-CODE-ECHO`로 검토 대기가 됩니다. 보안팀 계정에서 확정하고 돌아오면
그 대화에 결과가 찍혀 있습니다.

## 예비 — `예비_마스킹_고객명단.xlsx`

**본 순서에서 뺐습니다.** 규칙의 한계만 드러내고 그 자리에서 풀 방법이 없어 이야기가
열린 채로 끝납니다. 같은 한계를 07번이 **해결책과 함께** 보여줍니다 — 오탐이 나고,
검토 요청으로 사람이 풉니다.

한계는 회고 슬라이드에서 말로 짚습니다. 화면으로 보여주면 "안 됐다"로 읽히고,
말로 하면 "알고 있다"로 읽힙니다.

명단·동명이인·"명단에 없는 이름은 어떻게 되나요" 질문이 나오면 그때 꺼냅니다.

| 원본 | 나가는 것 |
|---|---|
| 김서준 · 박예린 | `[고객명]` — 명단에 있다 |
| 최도윤 · 정하윤 | **그대로** — 명단에 없다 |
| 연락처 4 · 이메일 4 | `[전화번호]` · `[이메일]` — 명단과 무관 |
| 계약금액 | 그대로 — 규칙이 없다 |

> 탐지 문제가 아니라 **데이터 문제**로 봤습니다(D23). 이름을 정규식에 박지 않고
> `customer` 테이블로 뺐습니다. 명단만 채우면 잡힙니다 — 코드는 안 바뀝니다.

## 미리 해 둘 것

- 파일을 **바탕화면 한 폴더**에 꺼내 둡니다 (예비 02번 포함 9개). 발표 중 파일 탐색에 시간을 쓰지 않습니다.
- `--verify`를 한 번 돌려 전부 일치하는지 봅니다. 정책이나 시드가 바뀌면 여기서 걸립니다.
- 08번은 실제 모델을 부릅니다. 회선이 불안하면 `ANSWER_PROVIDER=mock`으로 두면
  같은 장면이 네트워크 없이 나옵니다 — 검사 경로는 완전히 같습니다.

## 데이터

전부 합성입니다. 실제 고객·연락처·계약·티켓이 아닙니다.
김서준·박예린은 시드 고객 명단에 있는 이름이고, 최도윤·정하윤은 없는 이름입니다.
담당자는 기획서 10.1 원칙에 따라 `이OO` 형식을 씁니다.
