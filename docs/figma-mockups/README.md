# 피그마 반입용 화면 목업 — 사내 AI 게이트웨이

**캡처가 아니다.** 구현된 화면을 찍으면 "이미 만든 것"으로 읽혀서 구현 전에 그린 설계본으로 쓸 수
없다. 여기 11장은 `docs/screen-spec.md`(Figma 작업 지침)만 보고 다시 그린 와이어프레임이다.

캡처본이 필요하면 `docs/figma-assets/`에 따로 있다. 그쪽은 구현 결과이고 이쪽은 설계 입력이다.

| 항목 | 값 |
|---|---|
| 출처 | `docs/screen-spec.md` (기획서 5장 · 0.5 D1~D20) |
| 형식 | SVG (벡터) + PNG (2배율 확인용) |
| 프레임 크기 | 화면 10장 1280 × 800 · User Flow 1장 1440 × 900 |
| 충실도 | 회색조 와이어프레임 + 판정 4색 |

## 실제 앱과 다른 점

명세가 정한 골격을 따랐고, 구현 과정에서 뒤에 붙은 것은 넣지 않았다.

| 목업 | 실제 앱 | 왜 |
|---|---|---|
| 좌측 네비게이션 없음 | 좌측 사이드바 있음 | 명세 1장이 "헤더 중앙 탭 2개 (좌측 네비게이션 없음)"로 고정 |
| 우측 알림 레일 없음 | 알림 레일 있음 | 명세에 없다. 구현 중 추가된 것 |
| 세션 판정 집계 없음 | 있음 | 〃 |

목업이 명세와 어긋나는 게 아니라, 앱이 명세보다 앞서 나가 있다. 발표에서 "설계 → 구현" 순서로
보여줄 때 이 차이가 오히려 근거가 된다.

## 각 목업이 화면으로 증명하는 것

| # | 내용 | 근거 |
|---|---|---|
| 02 | 같은 문장이 개발팀에서는 규칙 0건으로 통과한다 | 7.3 부서별 정책 매트릭스 |
| 03 | 탐지 구간이 `[전화번호]` 라벨로 치환된다. `span` 오프셋이 아니라 라벨 문자열로 찾는다 | D3 |
| 04 | `차단`과 `마스킹` 규칙이 한 카드에 섞여도 최종 판정은 차단이다 | 충돌 해결 BLOCK > REVIEW > MASK > ALLOW |
| 05 | 언제 다시 시도하면 되는지 알려준다 — 모르면 사용자는 우회를 학습한다 | D20 |
| 07 | 직원 화면에는 확정 버튼이 없다 | 4장 책임 경계 |
| 08 | 규칙이 결정한 행은 AI 상태 칸이 비어 있다. 부서 필터에 정보보안팀이 없다 | 1.3, D2 |
| 09 | 규칙 finding은 `확정(규칙)` 배지에 버튼이 없고 AI 후보에만 버튼이 붙는다 | D6 |
| 10 | 확정 후에도 본문이 사라지지 않는다 | D14 |
| 11 | 마지막 전이는 폴링이 아니라 새로고침이다 | D12 |

## 색상 토큰

`screen-spec.md` 1.1 표 그대로다. 피그마에서 Color Style 이름을 토큰명과 맞춘다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `navy` | `#16202E` | 주 텍스트 |
| `blue` | `#2F5D8A` | 규칙 판정 라벨 · 선택 행 보더 |
| `red` | `#C2452D` | 차단 · 확정(위반) |
| `amber` | `#B7791F` | 마스킹 |
| `purple` | `#5B4B8A` | 검토 대기 · AI 후보 |
| `green` | `#2E7D5B` | 허용 |
| `gray` | `#6B7280` | 보조 텍스트 · 기각 |
| `card` | `#F4F6F9` | 카드 배경 |

골격선 `#C9D0D9`, 자리표시 `#E2E7ED`, 선택 배경 `#EFF2F6`, 페이지 경계 `#000000`은 명세에 없는
목업 전용 값이다.

배지는 Component + Variant(허용 / 마스킹 / 차단 / 검토 대기 / 제안됨 / 확정(위반) / 확정(규칙) /
기각)로 만든다. 색상만으로 구분하지 않도록 항상 한글 라벨을 같이 둔다.

## 피그마에 넣기

**이미 올려 뒀다** — https://www.figma.com/design/w28oqCfDnsTz3jPwHFKvFZ

페이지 `화면 목업 v1 — screen-spec.md 기준` 하나에 섹션 3개와 오버레이 1개가 있다.

| 레이어 | 내용 | 배치 |
|---|---|---|
| `SCR-01 직원 챗` | 01~07 | S1을 허브로 두고 분기 5개를 세로로 세움 |
| `SCR-02 관리자 감사 콘솔` | 08~10 | S5-b에서 오른쪽으로 이어지는 1행 |
| `Flow 화면 전이` | 11 | 1장 |
| `흐름 오버레이 (전이 화살표)` | 화살표 10 + 라벨 10 | 위 세 섹션 위에 겹침 |

프레임명은 위 표의 프레임명 열 그대로다. 도형·텍스트 레이어로 풀려 있어 그 자리에서 색·글자·간격을
고칠 수 있다.

### 흐름 오버레이

프레임을 격자로 늘어놓으면 S1이 5갈래로 갈라지는 구조가 안 보인다. 그래서 배치를 흐름 모양으로
바꾸고 전이를 화살표로 그었다. 그룹 하나라 레이어 패널에서 눈 아이콘으로 통째로 끌 수 있다 —
목업만 보고 싶을 때 끄면 된다.

전이 문구는 `11_user_flow`에 쓴 것과 같은 값이다. 화살표 색은 판정 토큰을 그대로 쓴다 — 색만
따로 외울 것이 없다.

| 전이 | 라벨 | 색 |
|---|---|---|
| S1 → S2 허용 | `200 ALLOW` | `green` |
| S1 → S3 마스킹 | `200 MASK` | `amber` |
| S1 → S4 차단 | `403 BLOCK` | `red` |
| S1 → S4′ 엠바고 | `403 BLOCK · 엠바고` | `red` |
| S1 → S5-a 폴링 중 | `202 PENDING` | `purple` |
| S5-a → S5-b | `aiStatus=COMPLETED` | `purple` |
| S5-b → SCR-02 목록 | `담당자 진입` | `gray` |
| 목록 → 상세 확정 전 | `행 선택` | `gray` |
| 상세 확정 전 → 확정 후 | `ACCEPT` | `blue` |
| 확정 후 → S5-b | `새로고침 (D12)` | `gray` · 점선 |

**마지막 하나만 점선이다.** 다른 전이는 시스템이 밀어주지만 이건 사람이 새로고침해야 넘어간다
(D12). 실선으로 그으면 폴링처럼 읽혀서 D12가 화면에서 지워진다.

엠바고(S4′)는 전이가 아니라 S4의 변형이라 `11_user_flow` 다이어그램에는 노드가 없다. 목업에는
프레임이 따로 있어 화살표를 하나 더 그었다. 허용·마스킹이 전송 후 S1로 돌아가는 복귀선은 긋지
않았다 — 열 갈래가 넘어가면 그림이 읽히지 않는다. 그 문구는 `11_user_flow` 하단 주석에 있다.

Autoflow(피그마 플러그인)는 MCP로 실행할 수 없어서, 같은 모양을 벡터 레이어로 직접 그렸다.
플러그인 산출물이 아니므로 Autoflow로 다시 열어 편집되지는 않는다. 화살표는 일반 벡터라
그 자리에서 끌어 옮기고 색을 바꿀 수 있다.

직접 다시 올릴 일이 생기면 `svg/*.svg`를 캔버스로 끌어다 놓으면 된다. PNG는 확인용이며 피그마에
넣지 않는다.

### 페이지 경계

흰 화면을 흰 배경에 놓으면 한 장이 어디서 끝나는지 안 보인다. 여러 장을 늘어놓는 캔버스에서 특히
그렇다. 그래서 `svg()`가 프레임마다 **검정 2px 경계**를 뷰박스 안쪽에 그어 둔다. 바깥에 그으면
잘린다.

**올라간 파일에는 아직 없다.** 지금 피그마에 있는 프레임 11장은 경계를 넣기 전 SVG에서 반입한
것이고, 반입 뒤에 배치·화살표 작업이 얹혀 있어 다시 올리면 그게 날아간다. 프레임 노드에 선을
거는 편이 맞고 호출 한 번이면 되는데, MCP 월 한도(Starter 20회)를 다 써서 이번 달에는 못 건다.

한도가 풀리면 프레임 11장에 `strokeAlign = 'INSIDE'` · `strokeWeight = 2` · 검정을 건다. SVG 쪽
경계와 같은 값이라 굵기가 어긋나지 않는다.

**둘을 겹치지 않는다.** 경계가 들어간 지금 SVG를 새로 반입하면 그 프레임에는 선을 걸지 않는다.
걸면 2px가 두 겹이 된다.

### 폰트

SVG는 Pretendard → Noto Sans KR → Apple SD Gothic Neo 순으로 지정한다. 올라간 파일에는 **Pretendard가
없어 Inter로 잡혔고**, 한글은 피그마 대체 글꼴로 정상 렌더된다 — 지금 보이는 화면은 맞다.

다만 그 자리에서 글자를 고치면 폭이 밀릴 수 있다. 피그마에 `Noto Sans KR`은 깔려 있으므로, 편집이
많아지면 텍스트 레이어를 그쪽으로 옮기는 편이 안전하다. 폭이 바뀌면서 위치가 틀어질 수 있어 일괄
교체는 하지 않았다.

## 다시 만들기

```bash
node docs/figma-mockups/build.mjs
```

의존성이 없다. 표준 라이브러리만 쓴다. PNG는 시스템에 깔린 Chrome으로 따로 렌더한다.

```bash
cd docs/figma-mockups
for f in svg/*.svg; do
  n=$(basename "$f" .svg)
  [ "$n" = "11_user_flow" ] && SZ=1440,900 || SZ=1280,800
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
    --hide-scrollbars --force-device-scale-factor=2 --default-background-color=ffffff \
    --window-size=$SZ --screenshot="png/$n.png" "file://$PWD/$f"
done
```

문구·규칙 코드를 고칠 일이 생기면 `build.mjs` 안의 프레임 블록만 손대면 된다. 규칙 코드와 의무·출처는
`backend/src/main/resources/db/migration/V2__seed.sql`의 규칙 8종에서 가져온 값이다.
