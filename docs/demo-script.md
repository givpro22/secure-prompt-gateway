## 0. 절대 규칙

1. **입력 문자열은 1절의 문자열을 그대로 붙여넣습니다.** 규칙 엔진 단위 테스트가 이 문자열에 고정되어 있습니다 (14장 리스크 대응). 오타를 즉석에서 고치지 말고 다시 붙여넣습니다.
2. Case A의 화면·대사는 **"규칙 2건"** 입니다 (0.5 D1).
3. 법령 조문 번호를 말하지 않습니다. "법령"·"개인정보보호법"까지만 말합니다 (7.2 하단 주석, 14장).
4. 화면 용어는 5.6 고정 — 허용 / 마스킹 / 차단 / 검토 대기 / 제안됨 / 확정(위반) / 기각. 발표에서 `ALLOWED` 같은 내부 값을 읽지 않습니다.
5. 확정 주체 필드는 **`decided_by`** 입니다. `decision_source`는 스키마에 없는 오기였고 기획서 4장·15.2에서 이미 교정되었습니다 (D10).
6. 발화 버블에는 **직원이 방금 입력한 문장이 그대로** 보입니다. 차단되어도 마찬가지입니다 (D15). 버블이 비면 오프닝의 "붙여넣은 스택 트레이스 안에 접속 문자열과 주민번호가 있습니다"(15.1)가 화면에서 성립하지 않습니다.
7. ACCEPT로 차단이 되어도 **상세 패널의 본문은 사라지지 않습니다** (D14). 사라지면 그 자리에서 설계 결함으로 읽힙니다.
8. **"분석"은 AI가, "검토"는 사람이 하는 일입니다.** 감사 콘솔의 AI 상태 컬럼은 공란 / 분석 중 / 분석 완료 / 분석 실패이고, 사람의 상태는 "검토 대기"입니다. 대사에서 두 단어를 섞으면 책임 경계 설명이 무너집니다 (D16 제안).

| 감사 콘솔에 방금 건이 없음 | 기간 필터를 오늘로 좁힘 → 그래도 없으면 시드에 넣어 둔 동일 케이스 완료 레코드로 설명 (10.1) | |
| DB·네트워크 장애 | 즉시 백업 영상 (3일차 11:00 녹화분) | 30초 이상 지체하지 않음 |

## 부록 — AI 엔진 전환 (선택 장면)

본편 Case A~E가 끝난 뒤 붙이는 추가 장면이다. **시연이 이 장면에 의존하면 안 된다** —
로컬 LLM이 죽어도 본편은 이미 끝나 있어야 한다.

### 사전 준비

백엔드를 두 번 띄운다. 8080이 비어 있어야 한다(다른 프로젝트가 쓰고 있으면 먼저 내린다).

```bash
SPRING_PROFILES_ACTIVE=mock SERVER_PORT=8080 ./gradlew bootRun
SPRING_PROFILES_ACTIVE=llm  SERVER_PORT=8081 ./gradlew bootRun
cd frontend && npm run dev:llm
```

발표 직전에 llm 쪽으로 아무 프롬프트나 한 번 던져 **모델을 미리 올려 둔다.** 첫 호출에는
모델 로딩이 붙어 10초가 넘을 수 있다. Chrome·Slack은 닫는다 — 모델이 4.6GB를 잡는다.

### 조작과 대사

| 시간 | 조작 | 화면 | 대사 |
|---|---|---|---|
| +0:00 | 헤더 셀렉터가 `AI 엔진: Mock`인 것을 보여준다 | 회색 점 | "지금까지는 Mock이었습니다" |
| +0:10 | 김OO(영업팀)으로 프롬프트 전송 | 후보 1건 `AI-CONTEXT` | "규칙은 'B사'만 잡았고, 여신 한도 초과는 AI가 올린 후보입니다" |
| +0:25 | 셀렉터를 `로컬 LLM`으로 바꾼다 | 점이 초록으로 | "코드는 그대로입니다. 백엔드 주소만 바뀝니다" |
| +0:35 | **같은 문장**을 다시 전송 | 같은 후보, 지연만 길어짐 | "이번엔 실제 모델이 판단했습니다" |

### 프롬프트

```
B사 견적 검토 부탁해요. 그 거래처 여신 한도는 이미 초과 상태입니다. 회의실은 3번으로 예약했습니다.
```

- 규칙 엔진 → `B사`만 (CONF-CLIENT-01, REVIEW)
- AI → `그 거래처 여신 한도는 이미 초과 상태입니다` (AI-CONTEXT, SUGGESTED)
- `회의실은 3번으로 예약했습니다` → 후보 아님

정규식으로는 만들 수 없는 판정이다. 이 장면이 로컬 LLM을 붙인 이유 전부다.

### 말할 수 있는 것과 없는 것

Mock 구간에서 **"지금 AI가 돌고 있습니다"라고 하지 않는다.** `case-client-generic.json`은
로컬 LLM 응답을 받아 적은 녹화본이다(`backend/src/main/resources/mock/ai/README.md`).
말할 수 있는 것은 "이 응답은 로컬 LLM이 실제로 낸 것"까지다.

### 실패 대응

| 증상 | 대응 |
|---|---|
| 셀렉터가 안 보임 | `npm run dev:llm`으로 띄웠는지 확인. `VITE_API_BASE_LLM`이 없으면 렌더되지 않는다 |
| 전환 후 화면이 빔 | 8081이 안 떴다. 셀렉터를 Mock으로 되돌리면 즉시 복구된다 |
| 응답이 30초 넘게 안 옴 | 모델 로딩이다. 되돌리고 넘어간다 — 본편은 이미 끝나 있다 |
| `ai_status=FAILED` | 설계된 폴백 경로다. "AI가 죽어도 사람 검토로 넘어간다"로 설명하고 지나간다 |

**배포본에는 이 셀렉터가 없다.** EC2는 7B를 못 돌리므로 `VITE_API_BASE_LLM`을 주지 않는다.
